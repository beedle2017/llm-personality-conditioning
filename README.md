# llm-personality-conditioning
Robust personality conditioning in LLMs

## Synthetic data generation

The generator creates behavioral, contrastive OCEAN pairs in
`data/pairs/{trait}.jsonl`. API keys are read only from environment variables;
copy `.env.example` for the variable names, but do not commit a `.env` file.
Gemini uses its OpenAI-compatible endpoint by default. Fill the model names in
`configs/data_gen.yaml` from the current AI Studio model list.

In Windows PowerShell, set a key and run the smoke test:

```powershell
$env:GEMINI_API_KEY = "..."
python scripts/generate_data.py --n-per-trait 10 --dry-run
python scripts/generate_data.py --n-per-trait 10
```

The full run uses approximately 700 requested pairs per trait, writes each
accepted batch immediately, and can be resumed after quota exhaustion:

```powershell
python scripts/generate_data.py --n-per-trait 700
python scripts/data_stats.py
```

Use `--trait openness` to run one trait and `--skip-judge` to defer judging.
The persisted counter is `data/pairs/.state/quota.json`; requests are rate
limited and quota errors back off with jitter. The run plan is: dry-run all
prompts, smoke-test a small generated sample by hand, then run the resumable
full generation and inspect statistics.

## Steering data

The contrastive pairs are loaded with `src/steering/data.py`. It prints the
raw row and split counts for each trait, preserves a complete train/dev split
when at least 50 dev rows are present, and otherwise creates a deterministic,
context-stratified dev split from unsplit/train rows. The loader returns
`TraitData.train` and `TraitData.dev` separately: compute steering vectors
from `train` only, and use `dev` only to select layers and alpha values.

```powershell
$env:PYTHONPATH = "src"
python -m steering.data
```

## Steering experiments: shared protocol (CAA vs BiPO)

The CAA and BiPO implementations must use this shared contract:

- [ ] **Same pairs:** use only `{prompt, pos, neg}` from
  `data/pairs/{trait}.jsonl`; neither method adds comparison pairs.
- [ ] **Same split:** load through
  [`src/steering/data.py`](src/steering/data.py). Build/train vectors only
  from `TraitData.train`; use `TraitData.dev` only for layer and coefficient
  calibration. Neither method uses BehaviorBench scenarios for training.
- [ ] **Same polarity:** `pos` is the high-trait pole and `neg` is the
  low-trait pole. For neuroticism, high means anxious/reactive and low means
  calm/stable. `scripts/run_caa.py` prints sample polarity checks.
- [ ] **Same formatting:** call
  [`format_pair`](src/steering/formatting.py), which uses the Llama 3.1 chat
  template and returns a response-only token mask.
- [ ] **Same model and seed:** use
  [`src/steering/common_config.py`](src/steering/common_config.py):
  `meta-llama/Llama-3.1-8B-Instruct`, `bfloat16` compute dtype, 4-bit NF4
  bitsandbytes quantization, and seed `20261026`. BiPO must use the same
  settings.
- [ ] **Same provenance:** pairs were generated by the scenario and pair
  templates in `src/data_gen/prompts/`, filtered by
  `src/data_gen/validate.py`, and judged with the configured generator
  `gemini-flash-lite-latest` and judge `gemini-3.5-flash-lite` from
  `configs/data_gen.yaml`.
- [ ] **Same steering hook:** use
  [`src/steering/hooks.py`](src/steering/hooks.py), which adds `alpha * v`
  at every residual-stream position.
- [ ] **Same coefficient mapping:** use `score_to_coeff(t, k)` from
  [`src/steering/common_config.py`](src/steering/common_config.py):
  `coeff = k * (t - 3) / 2`, so scores 1, 3, and 5 map to `-k`, `0`, and
  `+k`.
- [ ] **Same evaluation:** greedy decoding with
  `max_new_tokens=128`; use the same BFI and BehaviorBench setup and
  scenarios when those evaluations are available.

| Aspect | CAA | BiPO |
|---|---|---|
| Data use | Mean response-token activation difference over `train` pairs | Must use the same `train` pairs |
| Hyperparameters | Layer, response-token mean pooling, unit-norm vector, dev-calibrated `k` | BiPO-specific optimizer parameters, with `k` calibrated on the same dev rows |
| Layer choice | Dev sweep over layers 8-24, subject to invalid-rate constraint | Must use the same dev-only selection procedure |

### Data and run settings

The loader's raw and final counts are:

| Trait | Raw rows | Final train | Final dev |
|---|---:|---:|---:|
| openness | 330 | 256 | 74 |
| conscientiousness | 281 | 181 | 100 |
| extraversion | 288 | 188 | 100 |
| agreeableness | 195 | 148 | 47 |
| neuroticism | 263 | 163 | 100 |

Openness and agreeableness have smaller/noisy dev sets because their checked-in
files contain only 10 explicit dev rows and many missing splits. The fallback
split is deterministic and context-stratified with seed 42. The model is a
single Llama 3.1 8B Instruct checkpoint with bfloat16 compute and 4-bit NF4
quantization. The experiment seed is 20261026. CAA vectors use the mean over
response tokens and unit normalization. `k` is measured in units of the mean
activation norm at the selected layer.

### Results so far (CAA)

The current environment has an RTX 4060 Laptop GPU with 8 GB VRAM and the
required 4-bit dependency, but the gated Llama checkpoint was not available
locally and could not be downloaded during this run. Therefore CAA numerical
evaluation, generations, invalid-rate checks, perplexity, layer/k sweeps,
BehaviorBench, and BFI are marked **not run** rather than fabricated. The
committed result schema and placeholder configuration are in
[`artifacts/steering/results.csv`](artifacts/steering/results.csv) and
[`artifacts/steering/caa/config.json`](artifacts/steering/caa/config.json).
BehaviorBench and BFI are also **not run** because no implementation or
offline package was present.

The method-agnostic figures and tables are generated under
[`artifacts/steering/figures/`](artifacts/steering/figures/), including
`dose_response.png`, `layer_sweep.png`, `k_calibration.png`,
`context_heatmap.png`, `invalid_rates.png`, `summary.csv`, and `summary.md`.
With no CAA rows, the summary is intentionally empty and no traits can be
claimed to meet the monotonicity target.

To append BiPO rows, preserve the exact header and append rows with
`method=bipo` to `artifacts/steering/results.csv`, then run:

```powershell
python scripts/plot_steering_results.py
```

Exact reproduction commands:

```powershell
git switch feature/caa-steering
$env:PYTHONPATH = "src"
python -m steering.data
python scripts/run_caa.py
python scripts/plot_steering_results.py
python -m pytest
```

Known limitations and assumptions: the pairs are synthetic; the two smaller
dev sets have noisier calibration; only one model is specified; the gated
checkpoint may require Hugging Face access; the implementation assumes the
standard Llama decoder layer path `model.model.layers`; no BehaviorBench/BFI
numbers are inferred when unavailable.
